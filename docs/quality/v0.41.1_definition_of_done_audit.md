# Draftpaper-loop v0.41.1 Definition of Done 审计

> 审计日期：2026-08-23
>
> 审计范围：核心证据确认页可读性、技术审计分离、科学语义重确认、历史确认包迁移、只读 shadow、图表绑定表格证据，以及 v0.41.1 的发布合同。
> 发布边界：本文件记录本地发布候选的实现和验证事实；Git tag、GitHub Release 与远端 CI 只有在实际创建和运行后才能另行报告为完成。

## 结论

v0.41.1 将“作者应确认的科学决定”与“供追溯的技术审计包”正式拆开。默认交给作者的 `stage_summary.zh-CN.html` / `stage_summary.en.html` 是短小、可读、hash 绑定的决定页；完整活动、产物、验证明细和技术 hash 留在 `stage_audit.zh-CN.html`。Agent payload 和 `verify-next-action` 均优先给出可读页的项目相对路径及绝对路径，不再把审计包当作人工确认材料。

科学决定指纹只覆盖会改变结论含义的研究问题、数据/队列、方法与分析合同、运行、split、指标、图表系列和论断边界。HTML、PDF、引用映射、产物目录和路径变化不再单独重开 C3；一旦上述科学身份改变，或身份缺失、冲突、过期、未知，仍必须重开 C3。历史 v4/v5 包保持可读和可审计，但不会被静默当作新的科学确认。

本轮还修复了一个跨项目的证据身份缺口：同一数值指标在不同 cohort 中不再被误判为冲突；只有同时绑定 cohort、estimand、analysis spec、run、model、split 等身份的 figure source table 数值才可进入 canonical evidence registry。未绑定的草稿表仍可存在于技术审计中，但不会支持正文定量论断。

## 设计边界

- 可读确认页是决定材料，不是缩略技术日志；技术审计页仍是 hash、活动明细、文件清单和诊断的唯一完整载体。
- continuity 只减少“科学决定完全相同”时的重复 C3，不会替代 C3 对新数据、方法、队列、split、指标、图表或结论的人工确认。
- 迁移旧包不会伪造缺失的方法/分析身份。缺少正式身份的历史核心证据包只能迁移或触发新的 C3。
- figure table 的文件存在、行数或单个数值本身不是科学身份。缺少 cohort/estimand/analysis/run/model/split 绑定的表格不会晋升为 canonical evidence。
- fixture、showcase 和 shadow 只证明工作流合同；它们不构成真实论文的科学证据。
